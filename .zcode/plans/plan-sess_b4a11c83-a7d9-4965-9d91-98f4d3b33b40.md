# 修复 CORS 跨域配置错误

## 问题根因
当 `allowCredentials(true)` 时，CORS 规范要求 `allowedOriginPatterns` **不能是 `*`**。当前配置使用通配符并允许凭证，导致浏览器预检请求失败，后端没有返回 `Access-Control-Allow-Origin` 头部。

## 修复方案
在 `Movie_Rating_BackEnd/src/main/java/movie_rating_backend/config/WebMvcConfig.java` 中将 CORS 配置改为明确指定允许的域名，保留凭证支持。

### 具体修改
```java
@Override
public void addCorsMappings(CorsRegistry registry) {
    registry.addMapping("/**")
        .allowedOriginPatterns("https://movie-rating.pages.dev")  // 明确指定生产域名
        .allowedMethods("GET", "POST", "PUT", "DELETE", "OPTIONS")
        .allowCredentials(true)  // 保留，支持 JWT 认证
        .maxAge(3600)
        .allowedHeaders("*");  // 额外添加，允许所有请求头（包含自定义头如 Authorization）
}
```

### 修改说明
1. `allowedOriginPatterns("https://movie-rating.pages.dev")`：只允许生产环境前端域名访问
2. `allowedHeaders("*")`：额外添加，允许携带自定义头（如 `Authorization`）
3. `allowCredentials(true)`：保留，因为前后端分离需要通过自定义头传递 JWT token
4. 修改后无需改前端代码，直接提交部署即可

## 影响范围
- 本地开发不受影响（前端在 localhost:5173，不影响后端已有配置）
- 未来如有其他前端域名需要访问，需在 `allowedOriginPatterns` 中添加，或使用更灵活的动态配置方案
